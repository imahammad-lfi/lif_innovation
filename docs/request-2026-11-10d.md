## Mobile drawer performance — root cause and fix (10:07–10:31)
- Full production nav run (job_B31QdL4B, 6 phone profiles): all stages incl. drawer navigation passed, no header overlap,
  0 targets < 44 px, no errors. But Chromium first open = one long task: 175 ms at 1× CPU, 628 ms at 4×, 723 ms at 6×.
- Untraced event timing (Pixel 7, 1× CPU): click handler 146 ms on home (2,351 elements), 57 ms on /privacy-policy.
- Micro-benchmark of Radix *modal* side effects on the live home page: injected react-remove-scroll <style> ≈100 ms,
  body pointer-events:none ≈46 ms (inherited → whole-tree restyle), aria-hidden on body children 0.2 ms,
  inline html overflow:hidden 0.5 ms, inert on main/footer ≈45 ms. → modal mode costs a full-page style recalc twice.
- Fix (mobile-drawer.tsx): Radix Dialog modal={false} + full-screen layer (dim backdrop + panel, so nothing "outside"),
  usePageLock(): inline overflow:hidden on <html> (+ scrollbar-gap padding), aria-hidden on other body children,
  aria-modal="true". Radix keeps focus loop, Escape, initial focus, focus return. Overlay tap closes, touch-action:none.
  WebKit gotcha: a no-op exit animation fires no animationend there → closed layer never unmounts; the layer itself
  now fades (real value change) and the panel slides.
- Found while testing: on tablets (768–1023 px) the ATF pop-up could open over the open drawer (and on any width over
  the "Let's connect" form). event-promo-client now waits (1.5 s retries) while any [role=dialog][data-state=open]
  exists or a form field has focus.
- Contact hardening (route.ts): str() now replaces \p{Cc}, U+2028/2029 and bidi overrides with spaces and collapses
  whitespace; message uses text(): CRLF→LF, keeps line breaks (max two blank lines), drops other controls. Verified:
  accented / Devanagari / Arabic / Vietnamese names, ZWJ sequences unchanged.
- Deployed 10:30: eslint (full) 0, tsc 0, next build 0, 11 key routes 200, lf-web/lf-cms/docker active.
