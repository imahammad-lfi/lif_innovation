# Linkfields website — Next.js + Strapi rebuild

A faithful, component-by-component rebuild of **www.linkfields.com** on a modern, fully open-source stack.
Every page, section, text, image, breakpoint and interaction of the original was crawled and reproduced. The
content now lives in **Strapi 5** (PostgreSQL), so editors can change any text, image or section without a developer.

**Services update (2 Nov 2026):** the Services menu and pages now follow the five-service portfolio (Digital
Transformation, Intelligent Enterprise Platforms, Data & AI, Cyber Security, Talent Advisory & GCC) with their
sub-services, Linkfields IP products and engagement models. The 25 old service URLs redirect permanently to the new
pages. See [docs/SERVICES-PORTFOLIO.md](docs/SERVICES-PORTFOLIO.md).

**Products & Accelerators (3 November 2026).** A new menu tab groups the proprietary products by service line and lists
five reusable accelerators, following the client slide. It has a hub page, 13 product and accelerator pages, two new
CMS section components and a sectioned mega menu. The old `/linkfields-ip/*` URLs redirect. See
`docs/PRODUCTS-AND-ACCELERATORS.md`.

## Fonts — open source, no licence or copyright issues
The website uses **Plus Jakarta Sans** and **Inter**, both released under the **SIL Open Font License 1.1**: free for

## Repository layout

```
apps/
  web/        Next.js website (src/app routes, src/components/sections/* — one React component per CMS section)
  cms/        Strapi 5 CMS (src/api content types, src/components section schemas, scripts/seed.mjs importer)
seed/
  data/       Every page of the site as Strapi-ready JSON (generated by seed/transform + seed/custom)
  assets/     Original images/media (uploaded into Strapi by the importer)
  transform/  Python scripts that turned the crawled original site into the seed JSON
  custom/     5-service portfolio overlay: portfolio.json (menu), pages/ (36 new pages), apply.py, retired/
infra/        Terraform for AWS + Cloudflare, deployment scripts      (see docs/DEPLOYMENT.md)
docs/         DEPLOYMENT.md, SERVICES-PORTFOLIO.md (5-service structure, redirects), SECTION-CONTRACT.md (how sections are built),
              shared-blocks.md, QA-REPORT.md (fidelity vs the live site)
tools/        QA tools used to compare the rebuild against the live site (screenshots, computed styles, audits)
```

**Complete hand-over:** `tools/package_complete.sh [out_dir]` builds one archive,
`linkfields-complete-<date>.zip`. It contains all source code, `seed/assets`, the live Strapi media library
(`apps/cms/public/uploads`) and a PostgreSQL backup of the CMS (`database/linkfields_cms.sql.gz`), with
`HANDOVER.md` explaining how to restore it with or without Docker. It follows `.gitignore`, so secrets
(`.env` files), `node_modules`, build output and Terraform state are never included; CMS sign-in details are
handed over separately. The older `tools/package.sh` still builds the source-only and seed-assets archives.

## How content works

* **Pages** (`page` collection): `path`, `title`, `seo` and a **dynamic zone of sections**. 47 section types
  (hero, overview, stats band, carousels, accordions, contact form …) can be added, removed and re-ordered per page.
  The website renders any path that exists in Strapi, so editors can also create brand-new pages.
* **Global** (single type): header mega-menu, footer, social links, insights cards, contact-form defaults, default SEO.
* **Blog posts**, **news articles**, and **leads** (contact-form enquiries, write-only from the website).
* Publishing in Strapi calls the website's `/api/revalidate` webhook. The changed pages are refreshed within
  seconds without a rebuild, and Cloudflare/Next caches serve everything else.

## Local development

Requirements: Node.js 26 LTS, pnpm 10 (via `corepack enable`), PostgreSQL 18 (or Docker).

**Quickest: everything in Docker**

```bash
cp .env.example .env                                  # fill the secrets (openssl rand -base64 32)
docker compose up -d --build                          # postgres + cms (:1337) + web (:3000)
docker compose --profile seed run --rm seed           # import all pages, posts and images into Strapi
```

**Environments: `.env`, `.env.test`, `.env.prod`** (all git-ignored; each has its own committed template)

| File | Template | Command | Compose project | Website / CMS |
| --- | --- | --- | --- | --- |
| `.env` | `.env.example` | `docker compose up -d` | from `COMPOSE_PROJECT_NAME` | `WEB_PORT` / `CMS_PORT` (localhost) |
| `.env.test` | `.env.test.example` | `docker compose --env-file .env.test up -d --build` | `linkfields-test` | :3010 / :1337 (https://lfinew.lfidemo.com, CMS http://100.127.234.5:1337) |
| `.env.prod` | `.env.prod.example` | `docker compose --env-file .env.prod up -d --build` | `linkfields-prod` | :3000 / :1337 behind HTTPS |

On a server, copy that environment's template (`cp .env.test.example .env.test`), set its real addresses and fill in
the secrets. `WEBSITE_URL` (links in enquiry emails) and `CMS_PUBLIC_URL` (the "Open lead in CMS" button in the sales
alert) must be the environment's public addresses, never localhost. `docker compose` refuses to start when `SITE_URL`,
`WEBSITE_URL`, `CMS_PUBLIC_URL` or `CORS_ORIGINS` is missing, so an environment can no longer fall back to localhost.

Each file has its own secrets, compose project, database and media volumes, so the stacks never share data. Ports,
`SITE_URL`, `CMS_PUBLIC_URL`, `CORS_ORIGINS` and `IS_PROXIED` come from the file. `SITE_URL` is baked into the website build
and `CMS_PUBLIC_URL` into the admin bundle, so rebuild after changing them. Every new database needs its own
`STRAPI_LEAD_TOKEN` (CMS › Settings › API Tokens › website-leads › Regenerate).

**Without Docker**

```bash
# CMS
cd apps/cms && cp .env.example .env                   # point DATABASE_* at your PostgreSQL
npm ci && npm run develop                             # http://localhost:1337/admin — create the first admin user
npm run seed                                          # (in a second terminal, with the CMS stopped or running)

# Website
cd apps/web && cp .env.example .env.local
pnpm install && pnpm dev                              # http://localhost:3000
```

`CONTENT_SOURCE=local` makes the website read `seed/data` directly. This is handy for front-end work without a CMS.

Useful scripts:

| Where | Command | What it does |
| --- | --- | --- |
| apps/web | `pnpm dev` / `pnpm build` / `pnpm start` | develop / production build / serve |
| apps/web | `pnpm lint` | ESLint (Next + React hooks rules) |
| apps/cms | `npm run develop` / `npm run build` / `npm run start` | Strapi develop / admin build / serve |
| apps/cms | `npm run seed` | idempotent import of `seed/` into Strapi (`--only=pages,global,blog,news`; `--prune-pages` also deletes CMS pages no longer in `seed/data`; `--prune-posts` deletes blog posts and news articles no longer in the seed). Media are reconciled by file name, so a replacement image must get a new file name (e.g. `microsoft-colour.png`) or the old upload is re-used |
| apps/cms | `npm run seed:validate` | validate the seed JSON against the Strapi schemas |
| apps/cms | `npm run db:smoke` | boot Strapi against the configured PostgreSQL, check schema sync and published content |
| seed | `python3 seed/transform/build.py [family]` | regenerate seed JSON from the crawl, then apply the services portfolio overlay |
| seed | `python3 tools/publish_page.py <file.json>` | validate and publish one hand-authored page from `seed/custom/pages` |
| repo root | `tools/package.sh [out_dir]` | build the source and seed-assets archives (follows `.gitignore`) |
| repo root | `python3 tools/site_audit.py --local <url>` then `python3 tools/audit_report.py <json>` | compare layout with the live site and write a Markdown table |

## Security

* No secrets in the browser: Strapi is only called server-side, with a token restricted to `lead.create` for the contact form.
* Contact form: server-side validation (same rules as the original), honeypot field, per-IP rate limiting,
  optional Cloudflare Turnstile (`NEXT_PUBLIC_TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY`), and a Cloudflare WAF rate limit.
* Strict security headers (HSTS, nosniff, frame-options, referrer-policy, permissions-policy). Strapi runs with CSP and CORS restricted to the website origins.
* Origin servers accept traffic only from Cloudflare. Media are served from a private S3 bucket through CloudFront (OAC).

### Single-server hosting (preview / small installs)

For one-box hosting (the current preview runs this way) `infra/systemd/` contains two production units:

| Unit | Runs | Port | Notes |
|---|---|---|---|
| `lf-cms.service` | `strapi start` (`NODE_ENV=production`) in `apps/cms` | 1337 | starts the `pg18` PostgreSQL 18 container first and waits for `pg_isready` |
| `lf-web.service` | `next start` from a production build in the run directory | 3001 | reads published content from Strapi; refreshed on publish by the CMS webhook |

Both use `Restart=always` and are enabled at boot. Logs are in `/var/log/linkfields/{cms,web}.log`.

```bash
sudo cp infra/systemd/*.service /etc/systemd/system/ && sudo systemctl daemon-reload
sudo systemctl enable --now lf-cms lf-web
sudo systemctl restart lf-web          # after rebuilding the website (next build in the run directory)
```

These CMS `.env` settings are required behind an HTTPS proxy: `IS_PROXIED=true` and `PUBLIC_URL=<public CMS URL>`. Run `npm run build`
again after changing `PUBLIC_URL`, because the admin panel bundle embeds it. Also set `WEBSITE_REVALIDATE_URL=http://127.0.0.1:3001/api/revalidate?now=1`
and `WEBSITE_REVALIDATE_SECRET`, which must equal the website's `REVALIDATE_SECRET`. With these set, publishing in Strapi updates the website within about a second.

## Events, pop-ups and structured data (9 Nov 2026)

- Events are a Strapi collection (`api::event.event`). `/events` splits Upcoming and Past automatically by date (SAST), on the visitor's clock.
- A site-wide pop-up is an optional `Pop-up` component on an Event. Default window: from publishing until the end of the day after the event; on that day it shows a follow-up reminder only. Editor guide: `docs/EVENTS-AND-POPUPS.md`.
- Seed: `seed/custom/events.json` → `seed/data/events.json`; import with `npm run seed -- --only=events` (add `--prune-posts` to remove events no longer in the seed).
- After adding content types, run `pnpm exec strapi ts:generate-types` before `pnpm build` in `apps/cms`.
- JSON-LD: `Organization` on every page (from Global) and `Event` on `/events` (`src/components/seo/json-ld.tsx`). Absolute URLs follow `NEXT_PUBLIC_SITE_URL`, so set it to `https://www.linkfields.com` at domain cut-over.
- Contact form: organisation, phone (country code picker, validated with libphonenumber-js on the server) and area of interest are mandatory; leads store `phoneCountry`.
