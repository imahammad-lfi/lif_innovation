# Accelerator implementation report

Group: `accelerators` · 9 November 2026

## Planned and implemented section flows

All five pages follow the Accelerator narrative: hero → what it accelerates → reusable versus tailored scope → accepted artefacts/illustrative pattern → time-to-value prerequisites and engagement boundary → one or two connected items → contextual enquiry. The initial Delivery plan used five separate portfolio sections; rendered QA showed excessive length, so these were condensed into one seven-section flow with individually anchored portfolio categories.

Every page retains its URL and existing hero asset, has a concise British-English subtitle, six matching tabs, compliant SEO, no standalone social/insights/message banner, and exactly one final contact form. The first four pages use unified compact feature tiles with alternating navy/ink tones. Delivery uses the existing anchored portfolio inventory plus those tiles.

## Client input deferred, not invented

- Verified reusable-IP inventories for every accelerator: model/asset types, workflow/orchestration/integration assets, Power BI reporting assets, delivery pack contents, versions and support status; actual supported data formats, connectors and platforms.
- One approved real or redacted artefact per accelerator: model output, calibrated twin/scenario, underwriting workflow, Power BI report and delivery gate/evidence example. Include publication permission and outcomes with scope, baseline, period and comparator. Illustrative engagement patterns are supplied instead of fabricated proof.
- Commercial availability and ownership: adoption route, licence dependencies, reuse/handover rights and ongoing maintenance/support responsibility for each accelerator. Product licence/subscription/SaaS terms remain separate.
- Technical scope confirmation: evaluation methods, asset/process models, model/data architecture, latency/refresh conditions, Power BI licensing/capacity, security/permissions and hosting/operating ownership.
- Time-to-value evidence against like-for-like delivery records, including first usable output, assumptions, dependencies, work reused and work newly built. No individual delivery range or improvement metric is published.
- Confirmation of product/portfolio relationships and any product bundling; corporate deck relationships are described without assuming bundled licences.

No synthetic software screenshots, model inventories, named connectors, client cases, supported platform matrices, delivery weeks or outcome percentages have been invented. The examples explicitly describe illustrative engagement patterns. Actual approved proof can replace them later.
