# Request 2026-11-10 (k) — section tabs: land without half-visible cards, fit to any screen

User: on a product page (e.g. Linkworks), clicking a hero tab (Capabilities …) scrolls to the section, but depending
on the screen size the cards are left half visible at the bottom. Landing should adapt to the screen so the cards
show in full.

## Root cause
- Every landing (hero tabs, menu/footer #links, contact pop-up) put the section's top edge flush under the chrome
  (header 64/72/84 px + docked tab bar 49/53 px), whatever the screen size (`lib/landing.ts` sectionScrollTop,
  plus its own copy in `hero-tabs.tsx`).
- That top edge is mostly empty space: DeckStage top padding of 64/96/112 px, then eyebrow, heading and
  description, then a 40–48 px gap before the cards. On 1366×768, about 640 px is visible and the cards start
  about 310 px in, so rows ran past the fold. Between 1024 and 1279 px wide, 5 tiles wrap into 3 + 2 rows.

## Changes
- `lib/landing.ts` `sectionScrollTop` (used by every landing):
  1. skips the section's top padding, so the heading sits 24 px (LAND_BREATH) below the chrome;
  2. fit check on card blocks (`[data-land-card]`, `.card-surface`, `.acc-tile`; outermost only): if a card row is
     cut at the fold, the page moves down to show it in full while the h2 stays at least 4 px under the chrome.
     If that isn't possible, it moves up so the row starts whole below the fold, as long as the h2 sits at most
     LAND_MAX_GAP (150 px) under the chrome. Otherwise the heading wins (option A, agreed).
  3. computed in document coordinates, so the settle loop's repeated calls are stable.
- `hero-tabs.tsx`: `go()` uses `sectionScrollTop`. Scroll-spy also counts a section as current once the page is
  at its landing position, which can be slightly above the old line after an "up" adjustment.
- `globals.css`: `@custom-variant short` (min-width 1024px and max-height 820px). `feature-tiles.tsx`
  `short:mt-7` before the cards; `deck.tsx` DeckHeader description `short:mt-3`.
